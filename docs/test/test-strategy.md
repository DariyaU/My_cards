# Стратегия тестирования (Test Strategy)
**Проект:** Flashcards (My Cards)  
**Версия документа:** 1.0  
**Дата:** 2024-05-20  
**Статус:** Draft

## 1. Введение
Данный документ описывает стратегию тестирования мобильного приложения «Flashcards» (MVP). Приложение представляет собой оффлайн-инструмент для изучения иностранных слов с использованием карточек и алгоритма интервального повторения.

### 1.1. Цель
Обеспечить качество программного продукта, соответствующее требованиям SRS v1.0, путем выявления дефектов на ранних этапах и проверки функциональности, надежности и удобства использования.

### 1.2. Область применения (Scope)
Тестированию подлежат:
- Функционал управления наборами карточек (CRUD).
- Функционал создания и редактирования карточек.
- Алгоритм интервального повторения (SM-2 лайт).
- Локальное хранилище данных (SQLite/Hive).
- Пользовательский интерфейс (UI) и опыт взаимодействия (UX).

**Исключено из Scope (MVP):**
- Тестирование сетевого взаимодействия (приложение оффлайн).
- Тестирование безопасности серверной части (сервер отсутствует).
- Нагрузочное тестирование.

## 2. Подходы к тестированию

### 2.1. Уровни тестирования
| Уровень | Описание | Инструменты | Ответственный |
| :--- | :--- | :--- | :--- |
| **Unit Testing** | Тестирование бизнес-логики (алгоритм SM-2, валидация). | `flutter_test`, `mockito` | Разработчик |
| **Widget Testing** | Тестирование UI компонентов. | `flutter_test` (WidgetTester) | Разработчик |
| **Integration Testing** | Взаимодействие модулей (UI + БД). | `integration_test` | QA / Dev |
| **System Testing (E2E)** | Полные пользовательские сценарии. | Ручное тестирование | QA |

### 2.2. Типы тестирования
1. **Функциональное:** Проверка требований FR-XX из SRS.
2. **Нефункциональное:** Usability, Performance (< 2 сек запуск), Reliability (сохранение данных).
3. **Regression:** Проверка после изменений.

## 3. Критерии качества

### 3.1. Критерии входа (Entry Criteria)
- Код собран без ошибок.
- Unit-тесты проходят успешно.
- Тестовое окружение готово.

### 3.2. Критерии выхода (Exit Criteria)
- 100% тест-кейсов Critical/High выполнены успешно.
- Нет открытых багов S1/S2.
- Покрытие кода Unit-тестами ≥ 80%.

## 4. Окружение
- **OS:** Android 10-14.
- **Устройства:** Эмуляторы (Pixel), Физические (Samsung, Xiaomi).
- **Инструменты:** Flutter SDK, Android Studio, GitHub Issues.

## 5. Управление дефектами
- Баги регистрируются в GitHub Issues с лейблом `bug`.
- Серьезность: S1 (Blocker), S2 (Critical), S3 (Major), S4 (Minor).
- Жизненный цикл: Open → In Progress → Fixed → Verified → Closed.

## 6. Риски
| Риск | Вероятность | Влияние | mitigation |
| :--- | :--- | :--- | :--- |
| Потеря данных | Средняя | Высокое | Автосохранение, бэкапы БД |
| Ошибки алгоритма | Средняя | Высокое | 100% покрытие Unit-тестами |
| UI не соответствует макету | Низкая | Среднее | Widget тесты, Code Review |
