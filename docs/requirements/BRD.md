## 1. Введение

### 1.1. Цель документа
Данный документ описывает бизнес-требования к мобильному приложению «My Cards» для изучения иностранных языков (русско-английское направление). Приложение работает полностью оффлайн, без необходимости регистрации и доступа к интернету.

### 1.2. Область применения
Документ предназначен для команды разработки, тестирования и заказчика. Он служит основой для создания функциональных требований (SRS), пользовательских историй (User Stories) и тестовой документации.

---

## 2. Общее описание продукта

### 2.1. Видение продукта
Создать простое, быстрое и надежное мобильное приложение для изучения иностранных слов на основе карточек. Пользователь может создавать свои наборы слов, изучать их с помощью интервального повторения и отслеживать прогресс. Все данные хранятся локально на устройстве пользователя.

### 2.2. Целевая аудитория
- Изучающие английский язык (уровень Beginner to Advanced).
- Пользователи, предпочитающие оффлайн-режим (нет стабильного интернета, экономия трафика, приватность).
- Пользователи Android-устройств.

### 2.3. Бизнес-задачи
1. Предоставить удобный инструмент для запоминания лексики.
2. Обеспечить работу приложения без подключения к интернету.
3. Реализовать механизм интервального повторения для эффективного запоминания.
4. Минимизировать барьер входа (без регистрации, бесплатно).

### 2.4. Ключевые метрики успеха (Success Metrics)
- **Установка и запуск:** Пользователь успешно устанавливает и запускает приложение в течение 2 минут.
- **Создание набора:** Пользователь создает первый набор карточек в течение 5 минут после первого запуска.
- **Удержание:** Пользователь возвращается к приложению минимум 3 раза в неделю (streak).
- **Производительность:** Время загрузки приложения < 2 секунд, время отклика UI < 100 мс.

---

## 3. Ограничения и допущения

### 3.1. Ограничения (Constraints)
- **CR-01:** Приложение работает только на платформе Android (MVP).
- **CR-02:** Полное отсутствие сетевого взаимодействия (оффлайн).
- **CR-03:** Отсутствие серверной части и облачного хранения данных.
- **CR-04:** Отсутствие аутентификации и системы пользователей.
- **CR-05:** Поддержка только двух языков интерфейса: Русский и Английский (MVP).
- **CR-06:** Только текстовый формат карточек (без изображений и аудио в MVP).

### 3.2. Допущения (Assumptions)
- У пользователя есть устройство на базе Android (версия 8.0+).
- Пользователь понимает базовые принципы работы с карточками (вопрос-ответ).
- Данные не синхронизируются между устройствами (риск потери данных при удалении приложения лежит на пользователе).

| ID | Функция | Приоритет (MoSCoW) |
|----|---------|---------------------|
| F-01 | Создание наборов карточек (Deck) | Must Have |

| F-03 | Режим изучения "Карточки" (переворот) | Must Have |

## 5. Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Потеря данных пользователем (удаление приложения) | Высокая | Критическое | Добавить функцию экспорта в JSON (резервное копирование). |
| Низкая производительность на старых устройствах | Средняя | Среднее | Использовать легковесные решения, оптимизировать БД (Hive/SQLite). |
| Сложность реализации интервального повторения | Средняя | Высокое | Использовать упрощенную модель Leitner или SM-2 лайт. |
